# Serial mode

On when every unfinished ticket sits in one chain. Nothing can run in parallel, so the chain keeps one worktree and the full suite runs every 3 merges instead of after every merge. The rest of the Loop stands: each ticket still gets its own red-green check, review and merge.

- **One worktree for the chain.** `WT=<parent of the repo root>/<repo basename>-<chain's first ticket id>`, branch `build/<chain's first ticket id>`. If it exists, reuse it. Otherwise `git worktree add -b <branch> <WT> <BASE>`, then symlink each path in `.worktreeinclude` from the repo root into it at the same relative path, skipping one that already exists. Dispatch implementers with no `isolation` and `Work only in <WT>: cd there first.` as the prompt's first line. Remove it only after the chain's last ticket merges.
- **Implementers.** Resume the same one per rule 7. In AFK mode, dispatch a fresh implementer per ticket into the same worktree instead of leaving the next ticket `todo`. The lead's 3-merge budget still applies.
- **Suite every 3 merges.** After each merge, `wf done <index> <id> <merge sha>` right away. Run the full suite (Loop 5) after the 3rd merge since the last suite run, after the chain's last ticket, and before Finish if any merge has not had one. Keep building the next ticket while it runs; never merge until it reports.
- **Suite fails.** Find the first merge since the last passing run where those tests fail: for each, oldest first, `git checkout --detach <merge sha>`, run only the failing tests, then `git checkout <the index's Branch>`. Then `git reset --hard <that merge's parent>` (this also rewinds the index rows after it; re-log any `wf ruling` it removed), `wf set <index> <id> "blocked: post-merge suite: <failing test names>"`, and stop the chain there.
